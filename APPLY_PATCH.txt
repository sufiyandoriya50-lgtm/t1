FLOODSHIELD PHASES 8–10 CONSOLIDATED PATCH

Apply this patch to the FloodShield backend root (the folder containing app/, migrations/, tests/, and run.py).

1. Back up your current project folder.
2. Extract this ZIP directly into the backend root, allowing the included files to overwrite matching files.
3. No database migration is included or required by this patch. The existing DeviceToken.token column and session tables are reused.
4. Activate your existing virtual environment.
5. Run:
   python -m compileall -q app migrations tests
   pytest -q
6. If tests pass, run:
   flask db current
   flask db heads

Important behavior changes:
- POST /api/notifications/device-token now requires {"token": "<FCM registration token>", "platform": "android|ios"}. Do not send a Firebase Installation ID (FID).
- POST /api/auth/firebase and /api/auth/firebase/link now return HTTP 410. Firebase is used only for FCM push delivery.
- Configure CORS_ORIGINS only for explicit browser frontend origins. Native Android clients do not need CORS.
- Production requires separate random SECRET_KEY and JWT_SECRET_KEY values of at least 32 characters, PostgreSQL, Redis-backed rate-limit storage, and Firebase service-account credentials for FCM.
- Email and phone password changes/recovery revoke active sessions; users must sign in again.

The archive contains complete replacement files, updated/new tests, an environment template, and Phase 10 documentation (including API reference). It does not contain your .env file, database, uploads, service-account JSON, or virtual environment.
